# EngiProof skill

1. Read repository control files and the target source contract before editing physics.
2. Select a bounded published equation, figure, table or case with sufficient source inputs.
3. Preserve exact source traceability and source inconsistencies.
4. Create a paper-specific runnable study before generalizing it into shared code.
5. Add an independent mechanics check when physically possible.
6. Compare published vs reproduced/independent results and quantify discrepancies.
7. Classify evidence explicitly as `PUBLISHED`, `INDEPENDENT`, or `SOLVER_NEW`.
8. Never infer missing constants merely to improve agreement.
9. Tests prove software behavior; they do not automatically promote engineering evidence status.
10. Keep source PDFs and confidential project data outside public delivery.

## v0.1.1 runtime rules

11. Use the generic contracts in `engiproof/contracts/contracts.json`; do not create paper-specific status vocabularies when an existing contract fits.
12. Preserve an explicit evidence graph for studies that span source data, reproduction, independent checks, comparisons and discrepancies.
13. A comparison against published FE generated by the same source paper is not independent validation.
14. Keep unresolved source/figure inconsistencies as discrepancy records and continue other source-ready work.
15. Do not distribute copyrighted source PDFs or raster extracts; retain canonical filename, DOI, source SHA-256 and extraction provenance.
